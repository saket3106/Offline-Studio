# Decisions (fix/ui-voice-overhaul)

- `chat_validation_retries` is ignored (max_retries=0): validation never regenerates a real answer; one bounded recovery only when there is no answer (empty/echo). Opt-in bulk merge stays for tests.
- "in N words" with N>25 and no "exactly" is a soft target (±25%, informational only); "exactly N" stays strict but is not retried.
- Length cutoff: keep the streamed draft, trim to the last complete sentence, offer Continue; voice keeps its existing continuation.
- Deep-mode selective review kept: its draft is hidden, so nothing visible is wiped.
- Qwen thinking switch left as-is: the installed Qwen3.5 template branch is detected and thinking is already off outside Deep.
- Research failure answers locally with a quiet notice instead of posting the pipeline error.
- Docs/ledger live in Source (the git repo); evidence stays in ../offline-studio-fix/evidence.
- Context size not raised (no VRAM measurement possible at ~2 GB free RAM).
- Microphone permission remembered only for the app's own file:// origin.
- Build/install: `tools/release_inplace.py prepare|build|install|rollback` (SDK Python at Recovery\Engineering\reports\production-repair-20261021\sdk-build-input-env). Same gated procedure as the 2026-11-04 and 2026-11-06 releases; prior authority = the release currently installed; each release root under Recovery\Current is one-build-only.
- Agent workspace picker: native OS dialog in the real app; the scripted Qt dialog remains only for offscreen (headless) test runs, which existing tests rely on.
- Bulk-select bar is icon-only in the narrow sidebar; every button keeps an accessible name and tooltip.
- Bridge methods call module helpers through globals() because tests exec bridge method bodies in an isolated scope.

- 2026-11-07: Live Voice reserves 1400 MiB of GPU memory for Whisper (llama.cpp `--fit-target` 512+1400 while voice is on); a chat model loaded without that room is reloaded once when voice starts. Trade-off: slightly fewer chat layers on the GPU during voice, in exchange for ~0.3 s instead of ~12 s transcription.
- 2026-11-07: Helper servers (llama-server, whisper-server, sd-cli/sd-server) are placed in a kill-on-close Windows job owned by the app, so they end with it even after a crash or force-close. The app process itself is NOT in the job, so apps and games the assistant launches survive. At startup the app also stops helper servers from its own Application folder whose parent app is gone (PID-reuse safe: a parent younger than the child counts as gone). Never touches processes outside the app folder.
- 2026-11-07: Live Voice loads Whisper on the GPU FIRST, then the chat model (llama.cpp --fit sizes it around Whisper's memory). Measured: the 1400 MiB fit reservation still left only 0.75-1.25 GB free after load, so it is no longer used for voice (mechanism kept, reserve 0). If a loaded model leaves too little room, it is unloaded once at voice start and reloaded right after Whisper is warm. During voice a GPU Whisper survives chat/speech loads and has no idle timer (60 s after voice ends). Reusing a warm Whisper never unloads the chat model for low RAM.

## 2026-11-09
- Live Voice ends on clear goodbyes, not just "end voice chat" (user report: "No nothing. Okay. Thank you. Nice talking to you. End this live voice" was answered with "say end voice chat"). Farewells ("enough for today, we'll talk tomorrow", "call it a day", "good night", "I have to go") and "end this mode / end live" end it at once; this replaces the earlier rule that casual goodbyes only asked for confirmation. Pleasantries before a command are ignored, and Whisper's "and" for "end" is accepted only when the rest is a complete end command. Vague lines ("Okay, I'm done.") still go to the model classifier and are never an exit by rule. The chat model is told never to ask the user to say a phrase; it may only ask "Do you want me to end Live Voice?", and a "yes" to that ends it.
- Image follow-ups ("make the apple green", "edit it", "remove the background") edit the latest generated image in that chat instead of creating a new one. They go straight to a FLUX reference edit (no vision model: it needs about 6.3 GB of free RAM, which this PC rarely has). The edit starts from the picture itself (img2img strength 0.72) with the source seed and size, so layout, background and unmentioned details stay. Verified on a 512x512 apple: only the colour changed.
- When settings pair a vision model with a projector from another family, a matching mmproj next to the model is used instead (header check must pass), and the choice is saved in the config.
- Email without a connected account opens Gmail's compose window in Chrome (or the default browser) with the draft filled in; the user presses Send there. "Send at" schedules the app to open that draft at the time (the app must be running). Connecting an SMTP account stays optional, for fully automatic sending. The app never presses Send in Gmail.
- WhatsApp messages ("whatsapp Mom that I'll be late", "message John on WhatsApp saying ...") make a card. Nothing opens until the user confirms. Confirming opens WhatsApp Desktop (whatsapp:// link; WhatsApp Web if not installed) with the message typed in, and the user presses Send. The app never presses Send, so a wrong contact match can never send a message. Phone numbers the user enters are remembered per name on this PC only (assistant_contacts.json). Scheduled messages open at the set time, and the app must be running.
- Reminders and alarms ("remind me in 10 minutes to check the oven", "remind me at 5 pm to call mom", "wake me up in 20 minutes", "set an alarm for 7:30 am") run as the existing local timers (up to 24 hours) with a "Reminder: ..." alert.
- Image model switched to the step-distilled FLUX.2 Klein 9B (unsloth/FLUX.2-klein-9B-GGUF, flux-2-klein-9b-Q4_K_M.gguf, 5,673,900,320 bytes, SHA-256 23cadc53…, FLUX Non-Commercial License like the base), downloaded with the owner's approval. A model file named Klein without "base" runs at 4 steps and CFG 1 whatever the preset (more steps or guidance only cost time); the base model keeps its preset steps and CFG and stays on disk. Measured on this PC: 512x512 2 m 20 s → 19 s, follow-up edit 2 m 39 s → 18 s, 4K wallpaper 243 s → 62 s (27 s generation + 30 s upscale). At normal viewing size the quality is comparable. At 100% zoom the base model keeps slightly finer, more natural detail, and the distilled model can garble small text such as number plates. Config backup: Application\offline_gpt_config.json.pre-distilled-20261109.bak.
- More steps do not add detail to the distilled Klein (owner asked, 2026-11-09). Fixed-seed sweep at 1024x576: 4 steps 27 s, 8 steps 40 s, 12 steps 57 s, with no visible detail gain, and the composition drifts. The lever is pixels. With the distilled model, 4K, 2K and 1080p requests now render natively at 1920x1088 (1088x1920 portrait, 1440x1440 square) and are finished with a centre-crop Lanczos resize plus light unsharp mask (0.3 s). ESRGAN runs only above 2.05x. On the 2K image ESRGAN added 108 s for no visible gain. 4K now takes 62-63 s, the same as 1024 + ESRGAN, with far more real detail at 100% zoom: headlight internals, reflections and background. The base model and plain requests keep their sizes.
- Image Detail levels (owner request 2026-11-09): a "Detail" chip in the composer and in Image Studio, saved in settings (flux_detail_level). Standard = today's size. Detailed = 1080p. Highly detailed = 4K, drawn at 1920x1088 and resized with sharpening, about 1 minute. Extremely detailed = the 4K picture redrawn in 6 overlapping 1408x1168 tiles (img2img, strength 0.4, same prompt and seed), cross-faded, about 4-5 minutes. A whole-picture second pass at 2560x1440 does not fit 8 GB of VRAM: it needs a 5.8 GB workspace for one block, and it failed with --max-vram 5.5, 6.4 and with offload. Strength 0.3 came out softer than plain 4K. Strength 0.5 added real fine detail but changed content (plate text, a stray hood stripe). The levels apply to new images only. A size typed in the prompt wins. "highly detailed" / "extremely detailed" in a prompt can raise the level (never lower it), and only with the fast model, because base-model 4K takes several minutes. If the tiled pass fails, the Highly detailed result is kept, with a notice.

## 2026-11-12 — Image turns are decided by what the message asks, not by an image being present
Owner report: after an image was generated (or left attached by "Create variation"), later prompts were edited into it,
and long new prompts containing "scale", "crop" or "enhance" answered "Resizing requires an image". Causes: send()
probed `select_image_operation(text, has_image=True)` and a loose "the/this + noun" regex to reuse the last image; the
selector picked crop/resize/upscale from any such word even with no image; an attached image always went to vision.
Now `router.image_turn_intent` returns generate/edit/resize/crop/upscale/describe/chat from the wording (µs, no model);
crop/resize/upscale need the command itself and an image; a new-picture request always generates (attachment ignored).
Only genuinely ambiguous turns ask the already-resident chat model in a background thread (3 s budget, never loads a
model); without one, `image_turn_fallback` decides. The "Which image should I edit?" stop is gone: the most recent
image is the target (a named file wins). Also fixed: router.py defined `_QUESTION` twice, so the Agent regex silently
replaced the image-question regex.
